            statistiche obsolete, parameter sniffing o un problema di
            cardinalità. Skew ≥ 10x è evidenziato in rosso,

      Esegui & history
      
        
      

        
      
          Cosa fa questa sezione
          
      
            Esegue una query contro un database SQL Server. Ogni esecuzione
            diventa una revisione immutabile salvata nella
            cronologia (Postgres), con SQL, piano d'esecuzione e statistiche.
            Puoi confrontare due revisioni per vedere cosa è
            cambiato nel SQL, e fare rollback per creare una
            nuova revisione che ripristina il testo di una versione
            precedente — senza cancellare nulla.

      Revisione
      
    
      
    
      
      
      
        Cos'è una revisione?
        
      Uno snapshot immutabile di SQL + piano d'esecuzione + statistiche di quella singola esecuzione. La cronologia non viene mai riscritta.
      
      
      

      
      Statistiche
      
      
      

      
      SQL della revisione 
      
      
      

      
      
        
      Carica SQL nell'editor: copia il testo nell'editor senza toccare la cronologia. Modifiche e successiva esecuzione creeranno una nuova revisione.
      
        
      Rollback: crea una nuova revisione con lo stesso SQL di questa. La cronologia resta intatta.
      
      
      

      
      
        
        
      
      
    
      
  
      

  
  
      
    
      
    
      
      
      
        Come si usa Planalyzer
        
      
      
      
      
        
      I 5 tab, in ordine tipico d'uso:
      
        
        
          
      1. Certifica query — incolla il SQL e ottieni score + findings contro 34 regole (Kornelis, Pinal Dave, best practice). Puoi disabilitare singole regole dal catalogo.
        2. 
          
      2. Analizza piano — carica un .sqlplan (stimato o effettivo) e ottieni analisi per statement, warning e top-operator.
        3. 
          
      3. Stimato vs Effettivo — confronta due piani della stessa query per trovare skew di cardinalità.
        4. 
          
      4. Multi-DB — confronta piani da ambienti diversi (dev/stage/prod, o tenant) e ottieni raccomandazioni comuni.
        5. 
          
      5. Esegui & history — esegui la query contro un DB, salva una revisione nella cronologia Postgres, confronta revisioni, fai rollback.
